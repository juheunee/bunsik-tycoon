# 2주차 클라이언트 구현 (A3·A4·A5)

기준 일정: [Notion 분식왕 개발 단계 및 일정](https://app.notion.com/p/415dbdc4ceb2815b8212c65bc7567a76), 2026-11-11~11-17.
사용자 확인에 따라 기존 README·SPEC 게임 계약을 사용한다.

## 구현과 실행

JDK 21 이상을 PATH에 설정하고 저장소 루트에서 실행한다.

```powershell
.\verify-game.cmd
java -cp out bunsik.client.ClientMain
java -cp out bunsik.client.ClientMain --preview
```

- A3: 메뉴 5종·밸런스·좌표·테이블 상태·불변 StoreSnapshot, STATE 왕복 변환.
- A4: 닉네임/IP/포트/모드 입력, 비동기 소켓 통신, 식당 렌더링, 이동·경계·안내,
  화면 크기에 따른 확대/축소, 포커스를 잃으면 이동 키 해제.
- A5: 메뉴별 표시 앞에서 SPACE를 누르면 기존 COOK을 전송한다. 식당 화면에서 서버 조리 상태를 표시하고, 이동을 유지한다. B3 완료 시 보유 음식은 서버가 갱신한다. 지정 표시 앞 SPACE로 폐기하고, 결과 화면에서 새 접속 또는 타이틀 복귀를 선택한다.
- 참고 이미지: `docs/screenshots/` 9장. 그림은 Sprites.java에서 직접 그렸으며 새 외부 이미지는 사용하지 않았다.
- 참고 이미지에 맞춰 StoreLayout에 오른쪽 부엌·테이블 2×2·캐릭터 시작 위치를 정의했다.
- 대기실·2P 화면·H 숨기기는 같은 스타일로 미리 볼 수 있으며 기존 LOBBY/STATE/READY 형식을 처리한다.

상단 **화면 미리보기** 메뉴에서 시작·식당·카운트다운·부엌·조리 중·완료·결과·대기실·2P를 선택한다. 조리 화면 미리보기는 표시용 스냅샷을 사용한다.

## 검증과 남은 의존 사항

`verify-game.cmd`는 Java 21 대상 빌드와 기존 채팅·STATE·NetworkClient·화면 검사를 실행한다. 화면 검사 이미지는 `out/screens/`에 생성한다. 그래픽 환경의 추가 검사 명령은 `java -cp out bunsik.client.SessionScreenTest`다.

B3는 GitHub main에 병합됐다. 최신 B3는 SPACE에 대응하는 INTERACT로 주문·서빙·청소·부엌 내 보유 음식 폐기를 처리한다. COOK은 서버 캐릭터가 부엌 범위에 있고 조리·보유 중인 음식이 없을 때 수락한다. 조리가 끝나면 COOK_DONE과 보유 음식 STATE를 전송한다. 이 계약에서 조리대와 폐기 표시는 클라이언트 조작 위치이며 실제 서버 판정은 기존 부엌 범위를 사용한다.

## 키보드 조리 서버 계약

아래 항목을 차민과 합의하고 서버에서 검증한 뒤 클라이언트에 연결한다. 기존 MessageType과 STATE 포맷은 현재 계약을 유지한다.

- **배치와 대상 선택** — 메뉴별 조리 위치와 픽업 위치, 폐기 위치, 각 상호작용 반경, 동률 우선순위, 이동 충돌 여부를 공통 배치로 확정한다. 현재 클라이언트 표시는 메뉴·폐기 위치 선택을 위한 초기 배치다.
- **조리대 상태** — 서버가 조리대 식별자와 소속 식당, 메뉴, 상태, 조리 잔여·전체 시간, 픽업 대기 음식을 제공해야 한다. 스냅샷에서 조리대별 상태를 구분하고 첫 게임 상태 또는 다시 하기에서 초기 상태를 전송한다.
- **요청 계약** — 기존 COOK 또는 위치 기반 INTERACT로 시작·픽업·폐기를 식별할 수 있는지 정한다. 서버는 요청 시의 위치, 대상, 조리대 상태, 보유 가능 여부를 확인한다. 요청과 수락·거절을 연결할 수 있어야 지연된 일반 TOAST와 구별할 수 있다.
- **점유 정책** — 한 조리대는 음식 하나를 조리하거나 보관한다. 조리 중·완성 상태에서 새 조리를 거절한다. 픽업에 실패하면 조리대와 보유 상태를 유지한다. 픽업 승인 시 완성 음식 제거·보유 음식 갱신·조리대 대기 전환을 한 번에 적용하고, 다른 조리대 상태는 그대로 둔다.
- **동시 진행과 결과** — 서버 루프에서 조리대를 독립 갱신하고 플레이어의 이동과 분리한다. 종료 시 진행 중 조리·픽업 대기 음식의 처리를 정하고, 별도 총점을 제공하기로 합의하면 결과 필드와 호환 정책을 정한다.

합의 후 실제 서버에서 떡볶이와 김밥을 연속으로 시작해 멀리 이동한다. 각 위치에 완성 음식이 남는지 확인한 뒤, 완료된 조리대의 재조리 거절과 실패한 픽업의 상태 보존을 확인한다. 하나를 픽업해 비워진 조리대에서만 재조리할 수 있어야 하며, 다른 조리대의 진행·완성 상태는 유지되어야 한다.
