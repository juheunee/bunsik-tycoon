# 2주차 클라이언트 구현 (A3·A4·A5)

기준 일정: [Notion 분식왕 개발 단계 및 일정](https://app.notion.com/p/415dbdc4ceb2815b8212c65bc7567a76), 2026-11-11~11-17.
사용자 확인에 따라 기존 README·SPEC 게임 계약을 사용한다.

## 구현과 실행

JDK 21 이상을 PATH에 설정하고 저장소 루트에서 실행한다.

```powershell
.\verify-game.cmd
java -cp out bunsik.client.ClientMain
java -cp out bunsik.client.ClientMain --preview
```

- A3: 메뉴 5종·밸런스·좌표·테이블 상태·불변 StoreSnapshot, STATE 왕복 변환.
- A4: 닉네임/IP/포트/모드 입력, 비동기 소켓 통신, 식당 렌더링, 이동·경계·안내,
  화면 크기에 따른 확대/축소, 포커스를 잃으면 이동 키 해제.
- A5: 메뉴별 표시 앞에서 SPACE를 누르면 기존 COOK을 전송한다. 식당 화면에 서버의 조리 상태와 양손을 표시하며, 조리 중에도 이동할 수 있다. 지정 위치 앞 SPACE로 폐기하고, 1P 결과 화면에서 새 접속 또는 타이틀 복귀를 선택한다.
- 참고 이미지: `docs/screenshots/` 9장. 그림은 Sprites.java에서 직접 그렸으며 새 외부 이미지는 사용하지 않았다.
- 참고 이미지에 맞춰 StoreLayout에 오른쪽 부엌·테이블 2×2·캐릭터 시작 위치를 정의했다.
- A6 작업 전에도 대기실·2P 식당은 화면 미리보기에서 볼 수 있었다. 실제 접속에서는 B4의 입장·준비·카운트다운과 슬롯별 STATE를 받았고, 결과를 표시할 때는 1P와 2P 모두 연결을 종료했다.

상단 **화면 미리보기** 메뉴에서 시작·식당·카운트다운·부엌·조리 중·완료·결과·대기실·2P를 선택한다. 조리 화면 미리보기는 표시용 스냅샷을 사용한다.

## 검증과 남은 의존 사항

`verify-game.cmd`는 Java 21 대상 빌드와 기존 채팅·STATE·NetworkClient·화면 검사를 실행한다. 화면 검사 이미지는 `out/screens/`에 생성한다. 그래픽 환경의 추가 검사 명령은 `java -cp out bunsik.client.SessionScreenTest`다.

B3 이후 메뉴별 동시 조리와 양손 운반이 GitHub main에 병합됐다. 완성된 음식은 조리대에서 직접 집는다.

## 키보드 조리 서버 계약

클라이언트와 서버는 `StoreLayout`의 조리대·폐기 위치·설거지통 좌표와 상호작용 범위를 사용한다. 메시지 종류는 기존 `COOK`, `INTERACT`, `COOK_DONE`을 사용한다. 양손과 조리대별 상태 전송 형식은 [README 7-4](../README.md#7-4-통신-규칙)를 따른다.

실제 서버에서 떡볶이와 순대를 각각 시작해 두 조리가 함께 진행되는지 확인한다. 완성 음식을 두 손에 집고 각각의 주문 테이블에 서빙한다. 그릇이 남은 테이블은 기다리던 손님이 앉을 수 없고, 그릇을 집으면 바로 착석할 수 있다. 설거지통에서는 양손의 그릇을 한 번에 내려놓는다.

## A6 2P 경쟁 화면

- `WELCOME`의 접속번호로 대기실의 나를 표시한다. `READY`를 보내면 내 준비 상태가 반영된 `LOBBY`를 기다린다. 두 참가자가 준비하면 서버의 `START`를 기다린다.
- `START`의 내 슬롯을 기준으로 두 식당을 나눈다. `COUNTDOWN 0`과 내 `STATE`를 받은 뒤에만 조작할 수 있다. H키와 화면 버튼으로 상대 식당을 접어도 상대 상태는 계속 갱신된다.
- 내 시간이 0이 되면 입력을 막고 `GAME_OVER`를 기다린다. 2P는 결과 다음에 오는 `LOBBY`를 받아 두고 **대기실로** 버튼을 활성화한다. 1P의 **다시 하기**는 새로 접속한다.
- 화면 미리보기 메뉴는 `--preview` 실행에서 사용한다.

### 검증 명령

```powershell
.\verify-game.cmd
java -cp out bunsik.client.SessionScreenTest
java -cp out bunsik.client.ui.VersusScreenTest
java -cp out bunsik.client.ui.VersusScreenTest --real
```

같은 PC에서 실제 B4 서버 하나와 클라이언트 두 개로 3분 경기, 양쪽 무승부 표시, 대기실 복귀와 같은 연결에서의 재경기 시작을 확인했다. 자동 키 입력 검사는 Swing 액션을 호출했다. 물리 키보드·IME와 두 노트북 실전 테스트는 아직 남아 있다.

### B4 연결 정책

현재 계약에서 B4는 `GAME_OVER` 뒤 같은 소켓으로 준비가 해제된 `LOBBY`를 보낸다. 준비·취소 응답은 별도 응답 메시지 없이 `LOBBY`로 확인한다. 클라이언트는 연결 거절이나 종료 시 안내를 표시하고 타이틀로 돌아간다.

경기 중 한 명이 나갔을 때 남은 참가자에게 알리거나 경기를 조기 종료하는 정책은 B5에서 다룬다. 현재 서버는 남은 참가자의 경기를 계속 진행한다. 메시지에 경기 ID가 없으므로 재경기에서는 서버가 이전 경기의 전송을 끝낸 뒤 대기실 상태와 다음 `START`를 보내는 순서를 따른다.
